# Running TRANSPORT v1.6

Rebuilt for arm64 macOS with gfortran. See `Makefile.build` for how it's
put together (the distribution `Makefile` is stale against the shipped
`src/` tree — see the comments at the top of `Makefile.build`).

## Provenance

This is the Fermilab distribution of TRANSPORT (also issued as
SLAC-R-091/CERN-80-04/NAL-91), dated Dec 2002. `README` and `README-A`
are the original distribution's notice/license files (Fermilab Standard
Government Sponsorship Notice) — keep them as-is, they're not build
cruft. `ups/transport.table` is likewise original: a Fermilab UPS
("Unix Product Support") package table from the same 2002 distribution,
declaring how the product's `bin/` gets added to `PATH` under Fermilab's
package-management tooling; harmless to keep, not used by this repo's
own build.

## Build

```
make -f Makefile.build all      # bin/trns.exe
make -f Makefile.build bsheet   # bin/bsheet.exe (see caveat below)
```

## Running trns.exe

TRANSPORT reads its deck from Fortran unit 5 and writes the printed
listing to unit 6 — i.e. plain stdin/stdout redirection, no command-line
arguments:

```
bin/trns.exe < mydeck.dat > mydeck.out
```

Other logical units it may use, per the BLOCK DATA defaults in
`trnsblk.f` (`NIN,NOUT,NPUNCH,NDATA,NPLOT = 5,6,4,7,8`):

| Unit | Purpose                                   | File on Unix |
|------|--------------------------------------------|--------------|
| 5    | input deck                                  | stdin        |
| 6    | printed output                              | stdout       |
| 4    | punch output (rarely used)                  | `fort.4`     |
| 7    | binary output (`PLOT DATA` / `PRINT ALL` cards) | `fort.7` |
| 8    | plot file                                   | `fort.8`     |

`fort.7`/`fort.8` only appear if the deck actually requests them; move
them out of the working directory afterward (see `tests/trns` for the
canonical csh wrapper: it runs the binary then does
`mv fort.7 trns.bin` / `mv fort.8 trns.plot`).

## Deck format

Same input-deck syntax documented in the SLAC-R-091 TRANSPORT manual
(a copy lives at
`../venv-transport/E766/transport/SLAC-R-091-Rev3_TRANSPORT_manual.pdf`).
E766/B5-specific notes on the deck format are in
`../venv-transport/E766/TRANSPORT_deck_format.md`. Existing E766 beamline
decks (tune_2, tune_A–D) are in `../venv-transport/E766/transport/`.

Fitting is fully wired up — `FITTIN`, `SOLVE`, `STEPIT`, `EXPLOR`,
`REVISE`/`REPAIR` (for `USE` cards), `MCOUNT`/`SPREAD`/`MIDENT` (for
`ALIGN`) are all present in the library, unmodified. FIT cards and
variable-to-be-fit definitions in a deck should just work.

## Verification

Checked against the packaged regression deck:

```
bin/trns.exe < tests/trns.dat > /tmp/trns.out
diff <(tr '\r' '\n' < tests/trns.out) /tmp/trns.out
```

Output matches line-for-line. The only differences are:
- The `CHANGEDATE(TRMAIN ...)` version-stamp line — `tests/trns.out` was
  generated by an older intermediate build (`19990614`) than the final
  v1.6 source snapshot in `src/` (`19991129`); not a build defect.
- Sub-0.01% floating-point drift on computed envelope/matrix values
  (e.g. `214.2136` vs `214.2133`) — consistent with libm/trig precision
  differences between the original-era PowerPC/Absoft compiler and
  modern gfortran, not a logic error.
- Cosmetic: gfortran prints a leading zero for values `|x|<1` (`0.000`
  where the original printed `.000`) — a Fortran runtime formatting
  convention difference, not a deck/parsing issue.

## bsheet.exe (BSHEET) caveat

`BSHEET` (a separate program sharing this library, described further
down) needed two routines with no surviving source:
`DATE` (a vendor VAX/Absoft runtime intrinsic — reimplemented for real
in `build/date_stub.f`) and `MARKCK` (genuinely lost — stubbed as a
documented no-op in `build/markck_stub.f`).

`MARKCK` is only called `IF (ALIGN .OR. NUSE .NE. 0)` — i.e. only for
decks using TRANSPORT's alignment-error or `USE`-argument (macro
substitution) features. **Do not trust `bsheet.exe` output for decks
using `ALIGN` or `USE`** until a real `MARKCK` is written; ordinary
decks (like `tests/bsheet.dat`) are unaffected; that Meson West test
deck was fully verified (see prior session notes / diff against
`tests/bsheet.out` — every element, all FRD/station/easting/azimuth
fields matched, max floating-point drift 0.023 ft over the whole
beamline).

Run it the same way:

```
bin/bsheet.exe < tests/bsheet.dat > mydeck.out
```

`BSHEET` produces three sequential report sections per run: an
optics-style element listing (Z/X center in feet), a bare
name/type/station listing, and the full survey sheet (name, type, FRD
number pulled from deck comments, station, easting, northing, height,
azimuth/slope/roll in deg-min-sec) — informally "the Wehmann list",
after Alan (Allan) Wehmann, the Fermilab collaborator the format is
named for.
